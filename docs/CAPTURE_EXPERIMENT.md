# AF·단발 촬영 실험 화면

> **과거 연구 기록:** 0.8.12에서 BLE 위치 연동과 PC Remote 실험은 사용자 실기 피드백에 따라 종료·제거했습니다. 펌웨어 파일 분석도 제거했으며 라이브뷰 추가 계획은 없습니다. 아래 내용은 당시의 이력입니다. 현재 범위는 [인계 문서](HANDOFF.md)를 따릅니다.

> 0.8.9부터 Sony의 다른 모델도 미검증 경고와 실행 확인 후 AF·단발 촬영을 시도할 수 있습니다. 0.8.8 배포본은 ILCE-7C만 허용합니다. 기종별 실기 호환성은 확인되지 않았으며 기존 촬영 조건 검사는 유지됩니다.

0.8.0에서 **설정 → AF·단발 촬영 실험**을 연다. 실제 α7C 실기 확인 전 기능이다. 기존 PC Remote 실험 진단에는 촬영 명령을 연결하지 않았다.

## 준비와 실행

1. 진행 중인 가져오기가 끝나면 카메라의 스마트폰 제어를 끄고 PC Remote를 켠다. 연결 방법은 USB다.
2. 정지사진 M/P/A/S, 단일 촬영, Bulb 이외의 셔터속도, PC Remote 정지 이미지 저장 위치 ‘카메라만’을 사용한다. 기록 가능한 카드를 준비한다.
3. 케이블 연결 후 USB 권한을 허용한다. AF용 자동 초점 상태가 앱의 제한된 프로파일로 조회되어야 한다.
4. 먼저 **AF만 실행**을 선택하고 실행 확인란을 선택한다. 렌즈가 움직일 수 있으며 연결 과정에서 카메라 모드가 바뀔 수 있다.
5. 결과를 확인하고 전체 로그를 보관한다. **AF 후 단발 촬영 명령 1회**는 별도 새 세션이다. 실행 확인란과 추가 확인 대화상자를 모두 거쳐야 한다. 이 동작은 실제 셔터와 카드 기록을 일으킬 수 있다.
6. 완료 후 카메라 재생 화면에서 직접 사진을 확인한다. 앱은 저장 파일을 내려받거나 저장 성공을 확인하지 않는다.
7. 가져오기로 돌아가려면 PC Remote를 끄고 MTP를 선택한다. 필요하면 USB를 재연결한다.

앱은 카드 저장 대상 등 조건을 자동 변경하지 않는다. 제어 우선순위(`0xD25A`)만은 [카메라 쓰기 원칙](CAMERA_WRITE_POLICY.md)에 따라, 사용자가 그 실행의 확인란을 켰고 속성이 1바이트·쓰기 가능·활성으로 조회될 때 1(Application)을 쓴다. 쓴 뒤 재조회로 확인하고, 쓰기 전 값이 0이었으면 끝날 때 0으로 되돌린다. 로그의 `우선순위=` 줄에 처리 결과가 남는다. 해당 값이나 버튼 타입이 요구 조건으로 조회되지 않으면 실행을 거부한다. 거부를 우회하거나 지원 완료로 간주하지 말고 결과 로그를 공유한다. 세부 조건은 [3단계 프로파일](SONY_CAPTURE_STAGE3.md)을 참고한다.

## 결과 해석

| 결과/상태 | 의미와 다음 행동 |
| --- | --- |
| AF_LOCK_OBSERVED | 새 초점 잠금 전이를 관찰했다. 전체 셔터는 시도하지 않았다. 실제 초점 품질은 카메라에서 확인 |
| CAPTURE_SUBMITTED_UNCONFIRMED | 명령 제출 후 해제·관찰 절차 완료. 사진 저장 완료를 보장하지 않음 |
| FAILED, 전체셔터시도=true | 이미 촬영됐을 수 있음. 저장 결과와 카메라 상태를 확인하기 전 즉시 재시도하지 않음 |
| FAILED, 전체셔터시도=false | 이번 앱 실행의 전체 셔터 시도는 없음. 반셔터·모드 변경은 있었을 수 있음 |
| 반셔터/전체셔터해제 UNCONFIRMED | 해제 응답을 확인하지 못함. 반복 실행하지 말고 카메라 상태를 확인한 뒤 재연결 |
| NOT_ATTEMPTED | 해당 버튼 누름을 시도하지 않아 해제할 대상이 없었음 |
| PTP종료·자원종료 CONFIRMED | 종료 응답/자원 해제 확인. 물리 버튼 상태나 카메라 메뉴 원복 보증은 아님 |

실행조건은 PRIORITY_MODE, STORAGE_TARGET, DRIVE_MODE, FOCUS_MODE, STILL_MODE, SHUTTER_MODE, BUTTON_STATE, PENDING_OBJECTS, PROPERTY_MISSING/TYPE 등 고정 코드와 관련 속성 코드로 기록한다. 실제 속성값은 공유하지 않는다. 조건이 맞지 않거나 파서가 지원하지 않는 자료형이어도 유용한 실험 결과다.

이벤트 endpoint가 없으면 AF·촬영 준비를 시작하지 않고 자원을 닫는다. 준비 중 이벤트 큐가 계속 바쁘거나 기존 RAM 객체가 있으면 실행을 거부한다. 이전 사진을 읽어 소비하거나 삭제하지 않는다. 초점 상태가 이미 잠겨 있어 새 전이를 관찰하지 못하면 AF 실패로 끝날 수도 있다.

## 로그 공유

결과 미리보기의 **로그 공유**로 Android 공유 메뉴를 열고 수신자를 직접 선택한다. 앱을 닫거나 결과를 지우기 전에 보관한다. 자동 저장·전송은 없다.

로그에는 선택한 작업, 실패 단계/조건 코드, 프로토콜 버전, 명령의 시작·응답·실패, 경과시간, 버튼 해제·PTP/USB 종료 결과, 이벤트 코드만 포함한다. 사진·시리얼·기기 문자열·파일 경로·속성값·객체 핸들·원시 패킷·예외 메시지는 제외한다. 로그와 별도로 폰/Android, 카메라 펌웨어, 렌즈·촬영 모드, 연결 방식과 카메라 화면 메시지를 알려준다.

## 검증의 한계

모의 통신·기존 회귀 검사·빌드·서명 확인으로 배포한다. 실제 폰 UI·α7C AF/셔터·카드 저장·카메라 모드 복귀는 사용자 후속 확인 대상이다. AF의 논리 deadline과 네이티브 USB 호출 지연이 달라 물리 반셔터가 정확히 1초 이내에 해제된다고 보장할 수 없다. 모호한 촬영은 자동 재시도하지 않는다.
