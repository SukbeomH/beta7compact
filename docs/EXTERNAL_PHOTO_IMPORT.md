# 폰 사진·외부 이미지 추가와 편집

2026-11-18. 사진 탭에서 카메라 연결 없이 이미지를 추가하고 기존 편집기를 사용할 수 있게 했다. 0.8.8(21)에 포함한다. [배포 검증](verification/2026-11-18/release-0.8.8.md). 실기 확인은 사용자 후속 진행이다.

## 사용 순서

1. **사진 → 사진 추가**에서 Android 사진 선택기를 연다. 폰카로 찍은 사진과 선택기에 표시되는 이미지를 선택한다.
2. 파일·문서 제공자에서 선택하려면 **더보기 → 파일에서 사진 추가**를 사용한다. 제공자에 따라 클라우드 파일도 선택할 수 있으며 실제 다운로드/읽기는 해당 제공자의 지원·권한·연결 상태에 따른다.
3. 추가된 사진을 눌러 상세 화면을 연 뒤 **편집**을 누른다. 기존 LUT·색 보정·수동 왜곡·레시피·JPEG 저장을 사용한다. 가로 목록/미리보기에서는 기존 레시피 적용 동작도 유지한다.
4. 여러 사진 편집은 **더보기 → 사진 선택** 또는 사진 길게 누르기로 시작한다. 상단에 사진 추가를 배치하기 위해 기존 선택 버튼을 더보기로 옮겼으며 하단의 선택 수·공유·레시피 적용은 유지했다.
5. **외부** 필터와 타일 배지로 추가한 이미지를 구분한다. 카메라 가져오기는 기존 카메라 탭 또는 사진 더보기의 **카메라에서 가져오기**를 사용한다.

사진이 없는 상태에서도 사진 추가 버튼을 제공한다. 가져오기 상태는 추가·이미 있음·실패 건수를 나눠 표시한다. 중단하면 이미 완료된 항목은 남고 처리 중 항목의 새 사본은 정리를 시도한다. 화면을 벗어나면 진행 중 작업이 취소될 수 있다. 자동 레시피를 새 이미지에 즉시 적용하지 않고 사용자가 편집/적용한다.

## 파일과 보관 정책

- 새 저장소 읽기 권한이나 전체 갤러리 접근 권한을 요청하지 않는다. 시스템 선택기가 허용한 URI에서만 읽는다.
- 선택한 원본을 덮어쓰거나 삭제하지 않는다. JPEG 재압축 없이 바이트를 복사해 앱 소유 MediaStore 항목 `Pictures/beta7compact/External/`에 보관한다. 선택기 권한 만료 후에는 이 사본으로 편집한다.
- 한 번에 최대50장, 파일당64MiB다. 전용 임시 폴더는 한 항목씩 사용하고 정상/오류/취소 종료 시 파일을 삭제한다. 다음 추가 전에 이전 실행에서 남은 임시 파일도 정리한다. 실제 라이브러리 사본은 캐시가 아니며 추가한 사진 수에 따라 저장 공간을 사용한다.
- 실제 디코딩된 형식을 확인한다. JPEG·PNG·WebP가 대상이며 HEIC/HEIF·AVIF는 해당 기기의 BitmapRegionDecoder가 지원할 때만 추가한다. GIF와 카메라 RAW 파일의 외부 추가는 제공하지 않는다. 손상 파일은 검사 중 실패하거나 이후 편집에서 실패할 수 있다. 작은 영역을 읽는 확인이 전체 파일의 무결성 검사는 아니다.
- 기존 편집 결과는 JPEG/sRGB 경로다. 투명도·애니메이션·HDR/게인맵 등을 보존하는 편집 출력으로 표시하지 않는다. 큰 해상도는 추가/미리보기가 되더라도 기존 내보내기 메모리 제한 때문에 저장이 거부될 수 있다.
- 외부 목록의 시각은 추가 시각이며 상세 화면에서 **추가일**로 표시한다. 촬영 시각을 새로 추정하지 않으며 원본 EXIF는 사본에 바이트 그대로 남는다. 편집 결과에서는 기존 메타데이터 복사 정책이 적용된다.

## 중복·실패·카메라 경로 분리

`ExternalImageInput.kt`에서 제한된 스트림 복사와 SHA-256을 계산하고 `external:<hash>`를 원본 사본의 라이브러리 키로 사용한다. 같은 바이트를 다시 선택하면 이미 있는 항목을 재사용한다. 파일명이 같아도 바이트가 다르면 다른 사진으로 추가한다. 기존 외부 사본이 삭제되거나 바뀌었으면 새 사본으로 해당 행의 원본 URI를 복구한다. 다른 사진/카메라 원본의 삭제 동작은 없다.

중복 비교는 외부 추가 항목 사이에서 수행한다. 카메라로 가져온 동일 사진까지 자동 병합하지 않는다. `Photo.isExternal`은 계산용 확장 속성이며 DB 열을 추가하지 않는다. `PhotoDao.enqueue`, `RoomJournal`, 카메라의 완료 힌트에서 외부 항목을 제외해 다운로드를 잘못 건너뛰지 않게 한다.

새 MediaStore 항목은pending으로 생성하고 복사를 완료한 뒤 공개·DB 등록한다. 공개/DB 등록의 짧은 구간은 취소를 지연해 완료된 사진을 취소 정리에서 삭제하지 않게 한다. 이 전의 실패/취소에서는 이번에 생성한 항목만 정리한다. MediaStore와 Room은 하나의 원자적 트랜잭션이 아니므로 프로세스 강제 종료/기기 재부팅이 정확히 공개·등록 사이에 일어나면 연결되지 않은 사본이 남을 수 있다. 지속적인 작업 저널이나 자동 사본 삭제는 이번에 추가하지 않았다.

`PhotoRenderer`는 원본 형식에 EXIF 판독이 불가능하면 결과의 최소 JPEG 태그로 진행할 수 있게 했다. 원본 열기는 URI의 실제 MIME을 사용하고 공유는 기존 image/* 경로를 유지한다. 원본 URI 복구 시 미리보기도 새 URI를 기준으로 다시 읽는다.

## 변경 파일과 검증

- `library/ExternalImageInput.kt`: 복사 제한·해시·파일명/형식 정책·공개/등록/정리 순서.
- `library/ExternalPhotoImporter.kt`: URI 읽기·스냅샷·기기 디코딩 확인·중복 비교·MediaStore·Room 연결.
- `library/LibraryDb.kt`, `ui/MainScreen.kt`: 외부 원본과 카메라 다운로드 이력 분리. DB 스키마 변경 없음.
- `ui/PhotosScreen.kt`: 두 선택기·추가/중단/결과·필터/배지·선택 메뉴·빈 목록 안내.
- `ui/PhotoDetailScreen.kt`, `recipe/PhotoRenderer.kt`: 추가일·URI 갱신·EXIF 없는 형식 처리. 기존 편집/원본 보존 동작 유지.
- `ExternalImageImportTest.kt`: 신규9개. [빌드/검증 기록](verification/2026-11-18/external-photos.md).

자동 테스트는 바이트 보존/해시, 파일 한도와 읽기 중단, 이름/확장자 정책, 공개/등록 순서, 실패·취소 정리, 등록 중 취소 시 사본 보존, 카메라 큐/저널 분리를 확인한다. 실제 시스템 선택기·Android 디코더/MediaStore·폰 재실행·클라우드 제공자·이미지 편집/저장·다양한 EXIF 방향의 실기는 별도로 확인해야 한다. 이번 자동 테스트가 이러한 실기를 통과했다는 뜻은 아니다.
