# 편집 화면 구조 정리 1단계

2026-11-17. 오픈소스 재검토의 UX13 역할 기반 화면 골격을 적용한다.

## 변경

- `RecipeScreen.kt`: 세로/테이블탑 Scaffold의 상단에 뒤로가기·편집 제목, 하단에 비교·실행 취소/다시 실행·레시피 저장·사진 저장을 단일 고정 작업 영역으로 배치.
- 가운데 본문에서만 사진 미리보기와 조정 패널을 배치. 조정 패널만 스크롤하며 기존 전체 화면 스크롤/600dp 고정 패널 분기는 제거.
- 세로/짧은 창은 측정된 헤더·푸터를 제외한 본문에서 미리보기를 제한해 조정 공간 확보. 가로는 왼쪽 열의 헤더+사진과 오른쪽352dp 조정 패널을 나란히 표시. 전체 폭 헤더를 제거해 오른쪽 조정 패널은 화면 본문 상단부터 사용한다.
- 하단 작업은 FlowRow로 큰 글꼴에서 줄바꿈하며 실제 높이를 Scaffold가 측정. 저장 결과 안내는 고정 영역에 표시.
- 테이블탑은 헤더의 측정 높이를 반영해 기존 화면 중앙 경계를 가능한 범위에서 유지. 매우 짧은 화면에서는 조정 영역 확보를 우선한다. 실제 힌지 위치를 측정하는 구현은 아니며 기존 중앙 근사 방식의 한계를 유지.
- `UiPolicy.kt`, `EditorLayoutPolicyTest.kt`: 본문 높이에서 미리보기와 제어 영역을 배분하는 순수 정책과 짧은 창/200%글꼴/좁은 창/극소 크기/잘못된 입력 검사5개.

## 기능 보존 검토

다중 사진 선택·LUT/보관 레시피 선택·강도·세부 조정·초기화·원본 비교(버튼과 길게 누르기)·undo/redo·사용자 cube 가져오기/내보내기·결과 열기·오류 재시도·테이블탑 수동 전환·뒤로가기 확인을 유지한다. 사진 저장의 렌더 완료/저장 중 조건과 worker 호출, 레시피 저장 및 onArchived 연결은 유지한다. 레시피 저장 다이얼로그는 하나의 고정 호출로 관리한다.

기존 미게시 문구/접근성 변경과 조사 문서는 유지한다. 이번 작업은 UI1단계이며 이미지 로더 교체·저장 형식·USB 명령을 바꾸지 않는다. APK 버전은 개발 빌드의0.8.2(15) 그대로이며 GitHub 릴리즈 APK는 교체하지 않는다.

빌드 로그 및 실기 결과는 아래 추가 기록한다. 레이아웃 정책 테스트는 헤더·푸터를 제외한 본문만 검사하므로 전체 화면 접근성을 증명하지 않는다. TalkBack·실제 접힘 힌지·극단적으로 짧은 분할 창은 별도 실기 확인 대상이다.

## 추가 사용자 피드백: 사진 탭의 단일 사진 미리보기

`PhotosScreen.kt`도 일반 가로 탐색에서 왼쪽 열에 제목·선택·복구·필터·그리드를 모으고, 오른쪽 열에 미리보기·스크롤 정보·고정 적용 버튼을 배치했다. `MainScreen.kt`의 사진 탭 공통 제목은 PhotosScreen이 소유하도록 이동해 중복/전체 폭 헤더 공간을 제거했다. 다중 선택은 전체 폭 그리드를 유지한다.

폰에서 사진 포커스 변경에 따라 오른쪽 파일명이 갱신되는지 확인. 오른쪽 정보 시작y가1207에서913으로294px 상승했고 적용 버튼y1757은 유지됐다. 다중 선택으로 전환해 고정 적용 버튼이 유지되는 것도 확인했다. 사진 탭의200%글꼴·빈 필터·모든 크기 조합은 이번 추가 실기 확인에 포함하지 않았다.

### 적용 버튼 후속 보완

실기 캡처에서 사진 탭 적용 버튼이 화면 하단에 붙어 아래 곡선이 잘려 보이는 문제를 확인했다. 공통 ApplyRecipe 작업에 내부 여백(좌우/위12dp, 아래20dp)을 확보했다. 사용자 피드백에 따라 별도 작업 배경색은 제거했다. 버튼은 우측 정렬·최소폭160dp·최소높이48dp·모서리12dp로 통일한다. 다중 선택도 같은 작업 영역을 사용한다. 별도 메뉴나 실행 확인 단계는 추가하지 않는다.

별도 작업 영역 배경은 제거하고 하단20dp 여백·우측 정렬·버튼 크기만 유지했다. 최종 `assembleDebug lintDebug` 성공 후 폰에 개발 APK를 다시 업데이트 설치했다. [최종 빌드 로그](verification/2026-11-17/photo-action-final-build.log). 기능 변경까지의 Debug331개 회귀 검사는 통과했고, 마지막 배경 제거 후에는 빌드/lint만 재실행했다. GitHub 릴리즈는 게시하지 않았다.

### 다른 화면의 작업 영역 점검

편집 SaveActions의 surfaceContainer 배경도 발견해 화면 background와 동일하게 변경하고 하단20dp 여백을 적용했다. CameraPicker의 가져오기 고정 버튼은 하단8dp 여백을20dp로 보완했다. 사진 상세의 편집/공유는 스크롤 내용 안에 있고, 설정/레시피 카드·작업 진행·오류 배경은 내용/상태 구분 용도이므로 일괄 제거하지 않았다. 진단·공유 대화상자는 Material dialog 작업 영역을 사용하며 이번에 같은 커스텀 footer 배경은 발견하지 못했다. 이는 소스 검토이며 전 화면/전 테마 실기 검증은 아니다.

작업 영역 추가 점검 후 `assembleDebug lintDebug` 성공, 연결 폰에 개발 APK 업데이트 설치 성공. [로그](verification/2026-11-17/action-area-review-build.log). 카메라 미연결 상태의 CameraPicker 실제 버튼 검증은 수행하지 않았다.
