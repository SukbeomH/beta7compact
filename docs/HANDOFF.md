## 카메라 연결 기능 상태

| 기능 | 설정 화면 | 구현 범위 | 확인 상태 |
| --- | --- | --- | --- |
| BLE 위치 연동 | 위치 연동 › BLE 위치 연동 | 검색·페어링·전송·진단 | 이전 빌드에서 주변 BLE 광고 검색 확인. α7C 페어링·전송 미확인 |
| PC Remote 실험 진단 | 연구 · PC Remote 실험 | USB 세션 연결·속성 조회·조건 속성 기록 | 모의 통신 확인. α7C 실기 미확인 |
| AF·단발 촬영 실험 | 연구 · PC Remote 실험 | AF·단발 촬영, 실행별 확인에 따른 제어 우선순위 쓰기·되돌림 | 모의 통신 확인. 렌즈 동작·촬영·복원 실기 미확인 |
| Wi-Fi 연결 진단 | 연구 · PC Remote 실험 | PTP/IP 연결 인사·GetDeviceInfo, QR 텍스트 붙여넣기 | 이전 빌드에서 화면·입력·실패 경로 확인. α7C 실기 미확인 |

사용자가 카메라 실기 확인을 추후 진행합니다. 기기별 결과를 받기 전에는 연결·촬영 성공을 단정하지 마세요. Sony의 다른 기종도 원격 실험을 시도할 수 있지만 호환성은 미확인입니다. Sony 외 기종은 [호환성 조사 후보](CAMERA_MODEL_CANDIDATES.md)이며 연결 기능을 구현하지 않았습니다.

## 카메라가 있을 때 할 일

사용자가 아래 순서로 진행하고 각 단계의 결과를 공유할 수 있습니다. PC Remote 로그에는 촬영 조건 속성값, Wi-Fi 로그에는 사설 IP, BLE 로그에는 상태값이 포함될 수 있으므로 공유 전 미리보기를 확인합니다. SSID·암호·사진·좌표는 공유하지 않습니다.

### 1. BLE 위치 연동 — [점검 순서](BLE-LOCATION.md)

1. 카메라: 비행기 모드 끔, Bluetooth 리모컨 끔, Bluetooth 기능 켬, 이전 페어링 삭제 후 전원 재시작. USB는 뽑습니다.
2. 카메라의 페어링 화면을 연 채 앱에서 검색합니다.
3. 카메라를 선택해 페어링하고, 카메라에서 위치정보 연동을 켠 뒤 앱의 위치 전송을 켭니다.

볼 것: 카메라 광고가 잡히는지, 광고의 상태 바이트, 위치 서비스의 특성 목록(DD30/DD31 유무), DD01 알림 원문. 카메라 광고가 0건인데 "전체 광고"가 잡히면 카메라 쪽 문제이고, 범용 BLE 스캐너에는 보이는데 앱에만 안 보이면 매니페스트의 `neverForLocation`을 뺀 빌드로 비교합니다.

### 2. PC Remote 실험 진단 (USB) — [사용법](PC_REMOTE_DIAGNOSTICS.md)

한 번 실행하고 로그를 공유합니다. 여기서 나오는 값으로 이후 단계가 정해집니다.

- `광고프로토콜`: 0x00C8인지 0x012C인지. 노출 제어의 방식(단계 이동/직접 설정)이 갈립니다.
- `조건속성` 줄: 특히 `0xD25A`(제어 우선순위)의 타입·접근·값, `0xD222`(저장 위치), `0xD215`(대기 객체), `0xD221`(라이브뷰 상태).

### 3. AF·단발 촬영 실험 (USB) — [조건](CAPTURE_EXPERIMENT.md)

1. AF만 먼저 실행합니다. 2번에서 `0xD25A`가 0이었으면 "제어 우선순위 쓰기 허용" 확인란을 켭니다.
2. 로그의 `우선순위=` 줄에서 쓰기·재조회·되돌림 결과를 봅니다. 되돌림이 `CONFIRMED`가 아니면 카메라 다이얼이 평소처럼 동작하는지 확인합니다.
3. AF가 되면 단발 촬영을 한 번 시도하고, 카메라에서 사진이 저장됐는지 직접 확인합니다. 앱은 저장 완료를 확인하지 못합니다.

### 4. Wi-Fi 연결 진단 — [사용법](PC_REMOTE_DIAGNOSTICS.md#wi-fi-연결-진단-실기-미검증)

1. Wi-Fi Direct 방식을 먼저 시도합니다. 카메라의 PC Remote 연결 방법을 Wi-Fi Direct로 두고 화면의 이름·암호를 입력합니다.
2. 볼 것: 접속 여부, 카메라에 확인창이 뜨는지와 문구, `광고명령` 줄, 같은 조건으로 다시 접속되는지.
3. 그다음 폰 핫스팟 방식을 "주소 입력"으로 시험합니다. 볼 것은 카메라가 페어링을 요구하는지, 페어링 없이 연결 인사가 거부되는지 두 가지입니다.

카메라의 QR 화면에 나온 이름·암호가 PC Remote의 Wi-Fi Direct에도 통하는지도 함께 확인합니다. QR은 "스마트폰으로 제어" 쪽 화면으로 알려져 있고, PC Remote는 그 기능을 꺼야 씁니다.

## 실기 결과에 따라 이어질 작업

| 결과 | 다음 작업 |
| --- | --- |
| BLE 특성 목록에 DD30/DD31이 있음 | 확인란을 켠 실행으로 잠금 해제 쓰기를 시험. 이미 구현됨 |
| DD01이 모르는 값을 보냄 | `LocationPacket.enabled`에 값 추가 여부 결정 |
| PC Remote 진단 성공 | 촬영 후 관찰 시간 연장과 저장 확인 경로(`0xFFFFC001`) 설계. 지금은 0.3초만 관찰 |
| 단발 촬영 성공 | 노출 제어(ISO → 조리개 → 셔터속도 → 노출보정). 쓰기 원칙에 항목 추가 필요 |
| Wi-Fi 연결 진단 성공 | 기존 관찰 세션을 PTP/IP 전송으로 실행하는 단계. USB 컨테이너에 묶인 부분은 `SonySessionWireTransport`와 `SonyEventParser` |
| 핫스팟에서 페어링 거부 | 핫스팟 방식 보류. 페어링 절차는 공개 문서가 없고 우회하지 않음 |

USB 라이브뷰는 촬영이 실기에서 확인된 뒤 붙입니다. 전송 계층이 고정된 명령만 허용하고 응답 상한이 1MiB라서, 객체 조회 명령을 허용 목록에 넣는 설계가 먼저입니다.

## 정해 둔 것

- **카메라 쓰기**: [카메라 쓰기 원칙](CAMERA_WRITE_POLICY.md)의 허용 목록만 씁니다. 항목을 추가하려면 그 문서의 조건 8개를 채웁니다. 이 문서는 초안 상태로 들어갔고 소유자의 확정이 남아 있습니다.
- **공유 로그의 값**: PC Remote 진단은 조건 속성 13개의 값을 포함합니다. 기기 식별값·사진·좌표·원시 응답은 넣지 않습니다.
- **QR**: 앱 안에서 스캔하지 않고, 폰 카메라로 읽은 글자를 붙여넣습니다. 외부 라이브러리를 쓰지 않는 원칙을 유지합니다.
- **보류**: RAW 직접 현상(후순위), 카메라 내부 확장(이 기종에는 실행 환경이 없어 관찰만), Wi-Fi 액세스 포인트 방식의 페어링, 앱이 핫스팟을 직접 켜는 방식.

## 조사에서 나온 사실 중 문서에 없는 것

- 원형 α7C는 Creators' App 지원 목록에 없고 Imaging Edge Mobile 대상입니다. `docs/probe/DESIGN-initial.md`가 두 앱을 함께 적고 있어 고칠 필요가 있습니다.
- `docs/ARCHITECTURE.md`는 RAW 현상을 "LibRaw NDK"로 적고 `docs/TASK_M5B.md`는 외부 디코더 코드 사용을 금지합니다. RAW를 시작하기 전에 어느 쪽인지 정해야 합니다.
- α7C의 `SR2` 영역(촬영 화이트밸런스·색 행렬)은 암호화되어 있고 해독 방법은 공개 구현의 코드에만 있습니다. RAW 현상에서 이 값에 의존하는 설계는 근거가 부족합니다.
- `0xD25A`를 AlphaWire는 "Dial Mode"라고 부릅니다. 값이 1인 동안 카메라 다이얼보다 원격이 우선할 수 있습니다.

## 작업할 때 걸리는 것

- **서명**: 설치본과 같은 키로 빌드해야 덮어 설치됩니다. [SIGNING.md](SIGNING.md)를 먼저 확인하고, 서명이 다르면 앱을 지우지 말고 멈춥니다.
- **릴리즈**: BLE·원격·Wi-Fi 진단 변경 사항은 0.8.10에 게시됐습니다. 실기 검증은 별도로 진행합니다.
- **병합**: PR을 squash로 넣기 때문에, 같은 브랜치를 계속 쓰면 다음 `master` 병합에서 새로 추가한 파일이 "양쪽 추가" 충돌로 잡힙니다. 브랜치 쪽이 상위 집합인지 확인한 뒤 브랜치 쪽을 택하거나, PR마다 `master`에서 새 브랜치를 만듭니다.
- **과거 계약 검사**: `tools/check_m5a_contract.py`와 `tools/check_d2_contract.py`는 0.4.0 당시의 버전·브랜치·파일을 고정하므로 현재 릴리즈의 통과 기준이 아닙니다.
- **테스트 대역**: 단위 테스트는 `app/src/test/java/android/` 아래의 직접 만든 Android 대역 클래스를 씁니다. 새 Android API를 쓰면 대역도 넓혀야 합니다. Wi-Fi 접속(`AndroidWifiDiagnostics.kt`)은 단위 테스트가 없습니다.
- **폰 자동 입력**: `adb shell input text`는 폰 키보드가 한글 상태면 글자가 바뀝니다. 붙여넣기 동작은 손으로 확인해야 합니다.
