# α7C 인계 자료 통합 계획

> **과거 연구 기록:** 0.8.12에서 BLE 위치 연동과 PC Remote 실험은 사용자 실기 피드백에 따라 종료·제거했습니다. 펌웨어 파일 분석도 제거했으며 라이브뷰 추가 계획은 없습니다. 아래 내용은 당시의 이력입니다. 현재 범위는 [인계 문서](HANDOFF.md)를 따릅니다.

2026-11-17. 대상은 기존 beta7compact이며 세 인계 ZIP은 참고 자료다. 사용자 승인 범위는 아래 1~5단계다. 원격 제어·카메라 내부 실행은 포함하지 않는다.

## 보존할 경계

- 사진 가져오기·편집과 원본 보존을 유지한다.
- USB는 기존 UsbAccess 소유 규칙을 따른다. 별도 USB Lab 전송부로 교체하지 않는다.
- 카메라 쓰기는 [카메라 쓰기 원칙](CAMERA_WRITE_POLICY.md)의 허용 목록으로만 한다(2026-11-18 개정). 목록 밖의 설정 쓰기와 추측 Sony 명령은 추가하지 않는다.
- 연구 파일은 사용자가 고른 로컬 파일만 읽는다. 해시·파일명·헤더를 공유 진단 로그에 넣지 않는다.
- Linux 플러그인 시뮬레이터는 카메라 호환 코드가 아니므로 앱에 통합하지 않는다.

## 단계와 완료 조건

1. **기준선**: JDK/SDK/Wrapper와 기존 assembleDebug/test/lint 결과 기록. 실패는 소스 오류와 환경 오류를 구분한다.
2. **아이콘**: β7C 흰색 픽셀 테두리 참조로 전경·배경을 분리한다. 알파·마스크·리소스 컴파일을 검증한다. 실기 런처는 별도 검증이다.
3. **읽기 전용 진단**: 기존 DeviceInfo 파서와 USB 소유권을 재사용해 지원 명령·속성 목록을 표시한다. 광고된 기능과 실기 작동 확인을 구분한다. 속성 값 조회는 이번 단계의 필수 범위가 아니며 근거 없는 호출은 하지 않는다.
4. **로컬 파일 분석**: SAF 선택 파일의 크기·SHA-256·첫 64바이트를 스트리밍으로 확인한다. 오류·경계·취소를 검증한다. 카메라 펌웨어 추출 기능은 아니다.
5. **공식 지원 조사**: 원래 ILCE-7C와 ILCE-7CM2를 구분해 SDK/Command·플랫폼·연결 방식의 공식 근거를 기록한다. 연결 기기가 없다면 PC Remote 실기 검증은 미실행으로 남긴다.

## 병렬 작업과 통합

사용자 요청에 따라 아이콘, 진단, 파일 분석은 파일 소유권을 나누어 병렬 개발한다. 환경 복구·계획·공식 조사는 주 작업자가 담당한다. 결과는 기준선 확인 후 2→3→4→5 순서로 검토하며 최종 빌드는 한 작업자만 수행한다.

## 후속 범위

원격 촬영·설정 변경은 공식 근거와 ILCE-7C 실기 결과, 쓰기 정책 변경을 별도 결정한 뒤 설계한다. 기존 ARCHITECTURE.md의 장기 구상은 현재 읽기 전용 정책을 자동으로 변경하지 않는다. 카메라 내부 확장은 실행 환경과 복구 근거가 없는 상태이므로 독립 연구로 유지한다.

## 검증 기록

실행 명령·실패·결과는 docs/verification/2026-11-17/에 기록한다. 첨부 ZIP의 과거 테스트 로그를 이번 검증 결과로 계산하지 않는다.

- 4단계: 설정의 로컬 파일 분석 구현. 스트리밍·오류·협력 취소 테스트 추가.

- 빌드·테스트·환경과 미검증 항목: [검증 기록](verification/2026-11-17/README.md).
