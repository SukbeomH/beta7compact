# 수동 국소 보정 품질 실험

2026-11-18. 0.8.5부터 포함되는 실험 기능이다. 실제 인물의 개선 품질은 사용자 후속 평가 대상이다.

## 실행 순서

1. 설정 → 연구 · 사진 보정 실험 → **수동 국소 보정 · 실험**을 연다.
2. **JPEG 선택**으로 테스트 이미지를 고른다. 앱 전용 임시 파일로 복사하고 방향을 정규화해 표시한다.
3. 사진 위에서 보정할 부위를 눌러 중심을 지정한다. 검정 여백은 좌표 선택 대상이 아니다. 가로/세로 슬라이더로도 위치를 조절할 수 있다.
4. 영역 표시를 켜고 반경을 맞춘다. 반경은 사진의 짧은 변 기준5~50%다. 화면 터치 영역 자체를 얼굴로 자동 인식하지 않는다.
5. 기본 강도0에서 조금씩 높인다. 강도100%도 엔진의 제한된 변형량 안에서만 적용한다. 원본 보기/보정 보기와 영역 표시 끄기로 형태·배경을 비교한다.
6. **초기화 · 강도0**으로 돌아갈 수 있다. 강도0은 디코딩된 픽셀의 항등이며 JPEG 저장 시에는 재압축된다.
7. **실험 JPEG 저장**의 확인창을 거쳐 별도 결과를 만든다. 저장 중 조작/닫기를 제한하며 저장 취소는 정리 절차를 거친다.
8. 결과는 `Pictures/beta7compact/Experiments/`에 저장한다. 화면의 결과 열기로 확인한다. 기존 레시피/가져온 사진의 저장 결과 목록에는 연결하지 않는다.

입력 한도64MiB, 임시 입력 폴더 예약 한도128MiB. 미리보기 긴 변 최대1200px, 저장 긴 변 최대2048px이며2의 거듭제곱 샘플링으로 더 작아질 수 있다. sRGB로 처리하고 JPEG95로 인코딩한다. 촬영 EXIF·GPS·MakerNotes 등 원본 메타데이터는 복사하지 않는다. 원본 파일은 수정하지 않는다.

## 현재 기능의 의미

이 기능은 **수동2D 국소 변형**이다. 얼굴 검출·깊이·3D 복원·렌즈 프로파일·초점거리 재현·거리 추정·AF/MakerNotes 해석을 수행하지 않는다. 영역 안에서 원본을 조금 더 먼 반경에서 샘플링해 중심부 형상을 수축시키고, 영역 경계에서 변형량을0으로 연결한다. 얼굴 닮음이나 자연스러움을 보장하지 않는다. 사진 가장자리에서 샘플 좌표를 제한하므로 경계 신장이 보일 수 있다.

색 LUT/레시피·일괄 편집·기존 사진 저장·USB 가져오기/진단/촬영은 별도 경로로 유지한다. 인터넷 요청·사진 자동 전송·외부 얼굴 모델은 추가하지 않았다. 앱 자체의 기존 업데이트 확인 설정은 별개다.

## 사용자 인물 품질 평가 체크리스트

- 중앙 얼굴과 가장자리 얼굴을 구분해 비교. 가까운 촬영의 코 비율 문제와 화면 가장자리 신장을 따로 기록.
- 낮은/중간/높은 강도에서 눈·코·입·턱선·얼굴 닮음 유지 여부 확인.
- 안경·손·머리카락·가림, 두 사람 이상 사진에서 다른 사람과 배경에 영향이 있는지 확인.
- 배경 직선·문틀·식탁·경계가 휘거나 이음새가 보이는지 확인.
- 프리뷰/저장 결과의 중심·영역이 일치하는지 확인. 출력 해상도 차이를 고려해 비교.
- 원본 선호/결과 선호/차이 없음과 이유를 기록. 개선이 없는 사례도 실패 자료로 보관.
- 폰/Android, 입력 해상도, 보정 중심/반경/강도, 처리 지연·앱 멈춤 여부를 기록. 사진 공유는 사용자가 선택하며 얼굴 사진은 필수 제출 자료가 아니다.

실제50/85mm 촬영과 동등하다고 평가하지 않는다. 비교 촬영을 할 경우 같은 위치에서 크롭한 사진과 실제 촬영 거리를 바꾼 사진을 구분한다.

## 구현과 병렬 분업

- `perspective/LocalWarp.kt`, `LocalWarpTest.kt`: 국소 역매핑·bilinear 샘플링, 유한한 설정·픽셀 상한4,194,304·행 단위 취소 검사. 엔진 담당 서브에이전트.
- `LocalWarpPhotoIO.kt`, `LocalWarpOutput.kt`, `LocalWarpInput.kt`와 관련 테스트: JPEG 판별·sRGB·방향 정규화, 크기/메모리 예산, 동일 입력 snapshot, pending MediaStore 출력/취소 정리. I/O 담당 서브에이전트.
- `LocalWarpExperiment.kt`, `ui/SettingsScreen.kt`: 사진 영역 직접 지정, 슬라이더·비교·초기화·별도 출력 확인, 적응형 배치와 고정 작업. 주 작업 통합.
- 독립 검토 에이전트: 원본/미리보기/출력 일치·취소·자원 소유·실험 범위·접근성 경계 검토. 실제 품질 인증을 뜻하지 않음.

이미 화면에 표시된 Bitmap은 즉시 recycle하지 않고 참조 해제 후 GC에 맡긴다. 저장 과정에서만 소유하는 Bitmap은 finally에서 정리한다. 디코딩 전5개 버퍼 상당의 예산을 힙45% 이내로 제한하며 부족하면 거부한다. 실제 최대 사용량을 측정한 보증치는 아니다.

입력 snapshot은 교체/화면 종료 때 삭제를 시도한다. 비정상 종료 잔여 파일은 이후 복사 시24시간 초과분을 정리한다. 용량 부족으로 활성 파일을 임의로 삭제하지는 않지만,24시간 초과 정리는 활성 창을 추적하지 않으므로 하루 이상 열린 다른 창의 입력이 제거돼 저장이 실패할 수 있다. 시스템의 캐시 삭제도 재선택을 요구할 수 있다. 실패 시 원본이나 기존 결과에는 쓰지 않는다.

취소는 행/복사 구간/단계 경계에서 확인한다. 네이티브 JPEG 디코딩·인코딩과 일부 provider 호출은 즉시 중단을 보장하지 않는다. 출력 실패·취소 후 삭제를 시도하고 정리 오류는 원래 오류에 보존하지만 provider 자체의 고장으로 삭제가 실패할 가능성은 남는다.

## 검증 기록

첫 통합 빌드에서 Uri/String 연결과 Compose 제약 수신자 오류2개를 수정했다. 다음 실행에서 실제 자식 작업 취소가 부모 Job까지 취소한다고 잘못 기대한 테스트1개가 실패했다. 작업 Job을 직접 관찰하도록 테스트를 수정했으며 cleanup 동작은 변경하지 않았다. 같은 URI 재선택 재로딩, Dialog 뒤로가기, 입력 snapshot을 추가 검토했다.

[최초 빌드](verification/2026-11-18/local-warp-initial-build.log), [재시도](verification/2026-11-18/local-warp-retry-build.log). 최종 결과는 아래 추가 기록한다.

실제 인물 사진 평가·Android Bitmap/EXIF8방향/MediaStore 저장·파일 선택창·폰 UI·성능·메모리 최대값·TalkBack·모든 테마/창 크기는 미검증이다. 현재 연결된 Android 기기가 없다. 합성 픽셀과 가짜 출력 수명주기 테스트가 실제 사진 저장 검증을 대신하지 않는다. 기존 다른 채팅 프로토타입은 병합하지 않았으며 현 프로젝트에 독립적으로 구현했다.
