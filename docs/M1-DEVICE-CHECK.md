# M1 실기 확인 체크리스트

대상: ILCE-7C fw 2.03 ↔ Galaxy Z Fold8(Android 17/SDK 37). 아래 0.1.2 체크 항목은 서버 JVM 검증과 별개이며 현재 **미실행**입니다. 0.1.1 사용자 실기에서 raw 스위치를 켠 USB는 성공했고 기본 MTP와 BLE 검색은 실패했습니다. BLE 실패 당시 페어링 화면은 열려 있었고 다른 폰/IEM 연동 이력은 없었습니다. 개인 MAC·좌표·사진·실기 로그를 이 저장소나 이 문서에 붙이지 마세요. 필요하면 개인 저장소에 보관하고 공개 결과에는 통과 여부와 건수만 기록하세요.

## 설치와 권한

- [ ] 검증한 소스에서 로컬 빌드한 APK의 SHA-256을 개인 환경에서 확인한 뒤 사이드로드합니다. APK는 Git에 커밋하지 않습니다. 패키지는 `dev.sukbeomh.beta7compact`, 버전은 0.1.2(versionCode 3)입니다.
- [ ] 처음 실행 시 한국어 홈·가져오기·라이브러리·설정이 표시됩니다.
- [ ] 정확한 위치·근처 기기·알림 권한을 허용합니다. 거부 시 원인 안내를 확인하고 설정에서 다시 허용합니다.
- [ ] 접힘·펼침·회전·분할 화면에서 버튼과 날짜·사진 타일이 잘리지 않습니다.

## USB 가져오기

- [ ] 카메라에 테스트 카드와 충분한 배터리를 준비하고 데이터 지원 USB-C 케이블로 연결합니다. 다른 MTP 앱의 연결은 종료합니다.
- [ ] 카메라 USB 설정이 자동/대용량일 때 “카메라 설정 → USB 연결 → MTP” 안내를 확인합니다.
- [ ] MTP로 바꾸고 재연결했을 때 Android 앱 선택/열기와 USB 접근 권한 요청을 확인합니다.
- [ ] 홈의 USB 연결/권한 허용 또는 가져오기 새로고침 후 날짜별 JPEG·ARW 목록과 GetThumb 썸네일이 표시됩니다. HIF는 카드에 있을 때만 확인합니다.
- [ ] RAW+JPEG를 같은 촬영 쌍으로 표시하고 새 사진·가져온 사진을 구분합니다.
- [ ] 일부 선택 받기와 새 사진 모두 받기를 각각 실행하고 알림의 진행률·중단 버튼을 확인합니다.
- [ ] 갤러리 `DCIM/beta7compact/`에서 JPEG·ARW를 확인합니다. ARW MIME은 image/x-sony-arw입니다. 폰의 RAW 뷰어 지원과 가져오기 성공은 구분합니다.
- [ ] 카메라 원본과 수신 파일의 크기·SHA-256을 **개인 환경에서만** 비교합니다. 일치 여부만 공개 기록합니다.
- [ ] 가져오기 완료 전에는 부분 파일이 갤러리에 보이지 않습니다.
- [ ] 정확 원문·storage/parent/이름/크기가 같은 재연결 사진은 handle이 바뀌어도 ‘가져옴’입니다.
- [ ] fallback·시각 별명·다른 폴더/카드의 힌트 일치는 ‘확인 필요’로 선택 가능하며 ‘새 사진 모두 받기’에 포함됩니다.
- [ ] 같은 바이트의 확인 필요 사진은 다시 수신해도 새 게시 없이 기존 URI로 연결됩니다.
- [ ] 같은 이름·크기·촬영 문자열이더라도 다른 폴더/카드의 다른 바이트는 새 원본으로 게시됩니다.
- [ ] 원문 대기 행이 있는데 raw 보강 실패로 현재 원문을 확인할 수 없으면 전체 대기열을 게시 전에 중단하고 새로고침 안내를 표시합니다.
- [ ] v1/v2 DB 업그레이드 후 기존 키·URI·recipe를 보존하고, 비교가 필요한 기존 원본의 해시만 지연 계산합니다.
- [ ] 기존 완료 원본 조회·읽기 실패 시 새 게시 0·미완료 유지·임시 파일 정리·재시도 사유를 확인합니다.
  오류를 해제해 재개하면 기존 URI에 연결하고 게시 총 1개를 유지하는지 확인합니다.
- [ ] 사용자가 갤러리에서 지운 기존 URI는 행 부재를 확인한 뒤 새 게시를 허용하는지 확인합니다.
- [ ] 대량 수신 중 중단 → 같은 카드를 다시 연결 → 대기열 재개: 완료 파일은 다시 받지 않고 중단 파일은 처음부터 받습니다.
- [ ] 수신 중 케이블 분리·앱 프로세스 종료·저장 공간 부족 후에도 부분 게시·중복 게시가 없습니다. 앱을 다시 열고 USB 권한을 확인한 뒤 재개합니다.
- [ ] 다른 카드로 바꾸면 누락 대상 오류로 중단합니다. 카드 교체 후 오래된 handle을 그대로 사용하지 않습니다.
- [ ] 새 설치에서 raw PTP 스위치가 켜져 있고 목록·썸네일·JPEG/ARW 수신이 됩니다. 기존의 명시적 스위치 설정은 유지됩니다.
- [ ] raw 스위치를 끄고 MTP 실패를 재현하면 추가 버튼 없이 raw로 한 번 대체됩니다. 실패 단계 한 줄·성공 후 스위치 켜짐·앱 재실행 후 경로 기억을 확인합니다.
- [ ] MTP와 raw가 모두 실패하면 반복 대체 없이 중단합니다. 권한·카드 변경·기존 원본 비교 실패는 그대로 중단합니다.

## BLE 위치 동기화

- [ ] 필터 검색 15초 동안 company 빈 data 필터로 광고를 수신하는지 확인합니다. 첫 10초 이후 도착도 수집합니다.
- [ ] 필터에서 카메라 광고 0건이면 무필터 15초가 한 번만 이어집니다. 경로별 Sony 광고 수·유형 불일치 수와 다시 검색을 확인합니다.
- [ ] 검색 0건 시 페어링 메뉴·기존 다른 폰/IEM 페어링 점검 안내를 확인합니다. 안내만으로 실제 원인을 확정하지 않습니다.
- [ ] 이미 본딩된 ILCE-/DSC-/ZV-/ILME- 또는 저장된 카메라는 광고 없이도 목록에 표시되고 즉시 선택됩니다. 재본딩을 요청하지 않습니다.
- [ ] 카메라 Bluetooth를 켜고 페어링 메뉴를 엽니다. 앱에서 Sony 카메라 검색 → 대상 선택 → 양쪽 본딩 확인을 완료합니다.
- [ ] 카메라 위치정보 연동을 켭니다. 원격 Bluetooth 리모컨 등 충돌 가능한 카메라 설정은 카메라 안내에 따라 해제합니다.
- [ ] 앱에서 위치 동기화를 켜고 위치 타입 포그라운드 알림을 확인합니다. 야외에서 GPS 수신을 기다립니다.
- [ ] “BLE 응답 시간 초과”이면 카메라 위치정보 연동을 껐다 켠 뒤 앱 토글을 다시 켭니다. 최초 DD01 상태 알림이 실제 발생하는지 확인합니다.
- [ ] 카메라 GPS 표시와 앱의 마지막 전송 시각을 확인합니다. 실제 좌표는 앱 화면·공개 기록에 표시하지 않습니다.
- [ ] 5–60초 간격 변경이 적용됩니다. 화면을 끈 상태에서도 알림이 유지되고 전송 시각이 갱신됩니다.
- [ ] 위치 수신 후 새로 촬영한 테스트 사진의 위치·UTC 시각·시간대가 올바른지 개인 환경에서 확인합니다. 기존 파일을 앱이 수정하지 않습니다.
- [ ] 카메라 위치 연동 끔·카메라 전원 끔·Bluetooth 끔·권한 해제 시 실패 원인이 보이고 전송이 멈춥니다.
- [ ] 앱 또는 알림에서 끄면 서비스·GPS 사용·전송이 중단됩니다. 프로세스 종료 뒤 임의 자동 전송이 없습니다.
- [ ] 리모컨·Wi-Fi·EE 페어링 명령 쓰기 기능이 없습니다.

## 진단 공유

- [ ] 설정 → 진단 로그 공유에서 Android 공유 선택 화면을 열고 고정 이벤트 문구만 들어가는지 확인합니다.
- [ ] MAC의 일부도, 좌표·파일명·해시·광고 raw·예외 원문도 포함하지 않습니다. 공유 대상은 사용자가 선택합니다.

## 결과 기록

확인 날짜, APK SHA-256, OS/펌웨어 버전, 항목별 통과/실패/미확인과 오류 문구만 기록합니다. 본 체크리스트의 체크는 실제 수행 뒤에만 바꿉니다. Android 17의 작업 할당량·절전 정책·USB 드라이버·MediaStore RAW 처리·폴더블 UI는 실기 결과로만 확정합니다.
