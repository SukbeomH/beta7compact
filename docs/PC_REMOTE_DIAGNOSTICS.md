# PC Remote 실험 진단과 로그 공유

> **과거 연구 기록:** 0.8.12에서 BLE 위치 연동과 PC Remote 실험은 사용자 실기 피드백에 따라 종료·제거했습니다. 펌웨어 파일 분석도 제거했으며 라이브뷰 추가 계획은 없습니다. 아래 내용은 당시의 이력입니다. 현재 범위는 [인계 문서](HANDOFF.md)를 따릅니다.

> 0.8.9부터 Sony의 다른 모델도 미검증 경고와 실행 확인 후 진단을 시도합니다. 0.8.8 배포본은 ILCE-7C만 허용합니다. 모델별 실기 호환성은 확인되지 않았습니다. 비 Sony 장치는 이 원격 경로의 대상이 아닙니다.

0.7.0부터 **설정 → 연구 · PC Remote 실험 → PC Remote 실험 진단**에서 사용한다. 실제 α7C 검증은 아직 수행하지 않았으며, 연결이 어느 단계에서 실패하는지 수집하기 위한 기능이다.

0.7.1부터 화면에서 카메라 설정·테스트 순서·실패 시 공유 내용·가져오기 복귀 안내를 접고 펼칠 수 있다. 결과가 나오면 성공/실패 분류, 이벤트 0건, PTP·자원 종료 상태에 맞춘 설명이 표시된다. 모드 변경 경고와 실행 확인란은 접히지 않는다.

## 실행 순서

1. 진행 중인 사진 가져오기가 끝날 때까지 기다린다.
2. 원형 α7C(ILCE-7C)에서 스마트폰 제어를 끈다. 네트워크의 PC Remote 기능을 켜고 연결 방법을 USB로 선택한다.
3. 데이터 케이블로 연결하고 앱의 USB 권한 요청을 허용한다.
4. 모드 변경 안내를 읽고 이번 실행 확인란을 선택한 뒤 **실험 진단 실행**을 누른다.
5. 완료 후 결과를 확인하고 **로그 공유**로 공유 앱과 수신자를 직접 선택한다. 자동 전송하지 않는다.
6. 가져오기로 돌아갈 때 PC Remote를 끄고 USB 연결을 MTP로 선택한다. 필요한 경우 케이블을 다시 연결한다.

실행할 때마다 확인이 필요하다. 기존 **카메라 연결 진단 · 결과 공유**는 읽기 전용 경로를 그대로 유지하며 실험 명령을 보내지 않는다.

## 실행하는 것

활성 USB 구성·alternate를 조회하고 해당 still-image interface만 claim한다. USB 구성을 SET으로 바꾸지 않는다. 별도 세션에서 모델·광고된 명령을 확인한 뒤 Sony SDIO 연결 협상, 속성 snapshot 조회, interrupt endpoint가 있으면 최대 3회의 짧은 이벤트 poll, 종료를 시도한다. endpoint가 없으면 이벤트 관찰을 건너뛴 사실을 표시한다.

**SDIO 연결은 카메라 모드를 변경할 수 있다.** PTP 종료 성공도 카메라 메뉴 원복을 보장하지 않는다. PriorityMode·촬영·노출 설정·동영상 시작·파일 삭제·펌웨어 명령은 보내지 않는다. 가져오기·기존 진단과 같은 USB 잠금을 사용한다.

interrupt 이벤트는 Android `UsbRequest`로 읽는다. 정상 timeout에서는 요청 취소·회수 확인 뒤 무이벤트 결과를 기록한다. 취소한 요청의 회수를 확인할 수 없으면 연결을 폐기하고 실패로 기록한다. bulk timeout/프레이밍 오류에도 동일 연결을 재사용하지 않는다. 실제 Android USB 드라이버의 동작은 후속 실기 확인 대상이다.

## 로그 읽기

| 항목 | 의미 |
| --- | --- |
| 실패단계 | USB 발견·권한·구성·claim, 명령 전송 또는 수신 payload의 검증 단계 |
| response | 실제 수신한 PTP 응답 코드. OK여도 뒤의 payload 파싱은 실패할 수 있음 |
| 광고프로토콜 | 확장정보에 담긴 숫자. 실기 전체 호환성 보증이 아님 |
| 미지원속성 code/type | 엄격한 파서가 아직 처리하지 않는 속성과 자료형. 값과 원시 바이트는 제외 |
| 이벤트관찰·count | endpoint 유무와 관찰 결과. 이벤트 없음은 실패나 카메라 전체 미지원의 증명이 아님 |
| PTP종료 | NOT_OPENED/UNCONFIRMED/CONFIRMED. 마지막은 CloseSession OK를 뜻함 |
| 자원종료 | transport close 결과. factory 단계 실패는 생성/정리 확인 정보를 얻지 못해 UNCONFIRMED로 남을 수 있음 |
| 정리오류수 | 실패 뒤 종료 과정에서도 문제가 있었는지 확인하는 값 |

공유 대상은 숫자형 USB 선택 정보, 고정된 단계명·결과, 경과시간, 응답 코드, payload 길이, 프로토콜 버전, 속성 개수/미지원 타입, 이벤트 코드, 종료 상태다. 모델·펌웨어·시리얼 등 기기가 보낸 문자열, 경로, 사진, 원시 패킷, 예외 메시지는 포함하지 않는다. 속성값은 형식 2부터 `조건속성` 줄에 한해 포함한다: 드라이브·초점 모드·노출 프로그램·셔터속도(0x5013, 0x500A, 0x500E, 0xD20D, 0xD229), 초점 상태(0xD213), 대기 객체(0xD215), 라이브뷰 상태(0xD221), 저장 위치(0xD222), 우선 모드(0xD25A), 슬롯 남은 매수(0xD249), 버튼 상태(0xD2C1, 0xD2C2)의 타입·접근·현재값이며 기기를 식별하는 값은 없다. 다음 단계(우선 모드, 저장 확인, 라이브뷰)를 실기 한 번으로 판단하기 위한 것이다. GetExtDeviceInfo 응답이 비어 있으면 50ms 간격으로 최대 10회 다시 요청한다(libgphoto2·AlphaWire와 같은 동작). 필요하면 사용자가 모델/펌웨어와 실제 카메라 설정을 별도 메시지로 알려준다.

로그는 화면에만 유지하며 자동 저장·업로드하지 않는다. 앱을 닫기 전에 필요한 결과를 공유한다. 공유 버튼은 Android 공유 메뉴만 열고 수신자 선택·발송은 사용자가 한다.

## 알려진 제한과 검증

- 문자열·배열·128비트·새로운 enum 형식 등이 snapshot에 포함되면 현재 파서는 전체 snapshot을 거부할 수 있다. 미지원 타입을 기록한 로그도 유효한 조사 결과다.
- 성공은 연결·조회·종료 경로의 성공이며 원격 촬영·설정 제어 지원 완료가 아니다.
- USB 요청·timeout·정리, 세션·보고서·개인정보 제외는 모의 테스트로 검증한다. 실제 폰 UI·카메라 통신·공유 수신·모드 복귀는 이번 배포 전에 실행하지 않는다.
- 상세 구현: [오프라인 파서](SONY_OFFLINE_PARSERS.md), [별도 세션](SONY_REMOTE_SESSION.md). 빌드·서명·테스트·배포 결과: [0.7.0 검증](verification/2026-11-17/release-0.7.0.md).

## Wi-Fi 연결 진단 (실기 미검증)

설정 › 연구 · PC Remote 실험 › **Wi-Fi 연결 진단**. USB 대신 Wi-Fi로 PC Remote(PTP/IP, TCP 15740)에 닿는지만 확인하는 읽기 전용 단계다. 세션을 열지 않고 Sony 연결 명령·촬영·설정 쓰기를 보내지 않는다.

1. 명령 연결 → 연결 인사(InitCommandRequest: 앱의 무작위 식별값 16바이트와 이름 `beta7compact`) → 응답 대기 최대 30초. 카메라가 화면에서 확인을 받는 경우를 위한 시간이다.
2. 이벤트 연결(거부되면 100ms 뒤 최대 2회 재시도) → InitEventRequest.
3. 세션 밖에서 GetDeviceInfo 한 번. 카메라의 Ping에는 Pong으로 답한다.
4. 두 연결을 닫는다.

접속 방법은 두 가지다.

- **카메라의 Wi-Fi에 접속(Wi-Fi Direct)**: 카메라의 PC Remote 연결 방법을 Wi-Fi Direct로 두고 화면의 이름·암호를 입력한다. Android의 연결 승인 창을 거쳐 그 실행 동안만 접속하고, 카메라 주소는 그 네트워크의 DHCP 서버·게이트웨이에서 얻는다. 이름과 암호는 저장하지 않는다.
- **주소 입력**: 카메라와 폰이 이미 같은 네트워크(공유기, 폰 핫스팟)에 있을 때 카메라의 사설 IPv4 주소를 입력한다. Sony 도움말 기준으로 원형 α7C는 액세스 포인트 방식에서 페어링이 필수이고 "페어링 없이 연결" 메뉴가 없다. 페어링 때 클라이언트가 주고받는 내용은 공개 문서가 없어 앱은 페어링 절차를 수행하지 않으며, 거부나 시간 초과를 그대로 기록한다. 폰 핫스팟을 쓸 때는 WPA2·2.4GHz를 권하고(카메라 도움말에 WPA3 언급 없음), 카메라의 IP는 PC Remote가 액세스 포인트 방식으로 연결된 상태에서 "Wi-Fi 정보 표시"로 확인한다. 핫스팟에 붙은 기기 목록을 앱이 읽을 공개 API는 없다.

공유 로그에는 단계별 시간, 카메라의 로컬 주소, 연결 인사 응답 시간과 거부 사유, GetDeviceInfo 응답 코드, 명령 수, `0x9201`·`0x9202`·`0x9205`·`0x9207`·`0x9209`·`0x9280`·`0x9281`의 광고 여부가 들어간다. 네트워크 이름·암호·카메라 식별값·기기 문자열·시리얼은 넣지 않는다. 패킷 형식의 근거는 libgphoto2 `31a2f408` `camlibs/ptp2/ptpip.c`이며 코드는 가져오지 않았다.

실기에서 확인할 것: 접속 가능 여부, 카메라 확인창 유무와 문구, 광고 목록, 같은 식별값으로 다시 접속되는지, 진단 뒤 카메라가 정상으로 돌아오는지.
