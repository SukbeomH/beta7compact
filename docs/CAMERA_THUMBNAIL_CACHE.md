# 카메라 썸네일 캐시

카메라 사진 선택 화면에서 받은 썸네일 Bitmap을 앱 메모리에 최대 24MiB 보관한다. 화면 이탈·스크롤·가져오기 종료 후 다시 표시할 때 캐시가 남아 있으면 USB 요청과 JPEG 디코딩을 생략한다. USB 잠금을 얻은 뒤에도 캐시를 재확인해 대기 중 중복 요청을 줄인다.

저장소·부모 폴더·객체 핸들·파일 메타데이터 해시로 구분한다. 목록 스캔은 실제 카메라에서 수행하며 새 촬영·삭제를 확인한다. 갱신된 목록에서 사라진 객체의 캐시는 제거한다. USB 연결/해제 때 전체 캐시를 비우고, 이전 연결에서 진행 중이던 요청 결과가 새 캐시에 들어가지 않도록 세대 번호를 검사한다. 실패·빈 썸네일은 보관하지 않는다.

최근 사용하지 않은 항목부터 메모리 한도 안에서 제거하며 제거된 Bitmap은 화면에서 사용 중일 수 있어 강제로 recycle하지 않는다. 메모리 캐시는 연결 해제 시 비우지만, 앱 전용 cacheDir의 디스크 캐시는 재연결·프로세스 재시작 후에도 사용한다. 디스크 상한은 128MiB, 항목당 4MiB다. 최근 사용한 시각을 갱신하며 오래된 파일부터 제거한다. 운영체제가 캐시를 삭제할 수 있고, 이 경우 카메라에서 다시 읽는다.

USB 권한으로 얻은 카메라 serial·VID/PID의 SHA-256을 카메라 범위로 사용하고, 저장소·부모 폴더·파일 메타데이터 해시로 썸네일을 조회한다. 재연결 시 변할 수 있는 객체 핸들은 디스크 키에서 제외한다. serial 또는 원시 촬영시각이 없으면 연결 간 재사용을 하지 않는다. 원문 serial·파일명은 캐시 파일명이나 로그에 쓰지 않는다. 실제 썸네일 이미지 데이터는 앱 전용 캐시에 보관한다.

사진 목록 자체는 스캔 때마다 갱신한다. 같은 카메라에서 카드 교체/수정 후 파일명·크기·촬영시각·폴더까지 완전히 같은 다른 파일이 나타나면 메타데이터만으로 구분할 수 없다는 한계가 있다. 캐시는 사진 원본이나 가져오기 완료 판정에 사용하지 않는다.

검증: ThumbnailCacheTest는 재사용·LRU 용량 제한·삭제 항목 정리·연결 해제 후 늦은 결과 거부를 검사한다. DiskThumbnailCacheTest는 재생성된 캐시 인스턴스에서의 조회, 카메라 범위 분리, 용량 제한·항목 제한·오래된 항목 제거를 검사한다. 실제 카메라의 요청 횟수·스크롤 체감 속도·대량 사진 메모리 사용량은 실기 확인 대상이다.
