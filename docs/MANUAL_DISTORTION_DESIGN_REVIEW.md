# 수동 왜곡 조절 최종 적용안과 디자인 규칙 검토

2026-11-18. 대상은 기존 편집기 안의 전체 사진 수동 왜곡 조절이다. [UIUX_DESIGN.md](../UIUX_DESIGN.md)의 UX01~12와 [오픈소스 재검토](UIUX_OPEN_SOURCE_REFERENCES.md)의 UX13~16을 대조했다.

**검토 범위는 코드·프로젝트 규칙이다.** Product Design audit 절차를 확인했지만 최신 개발 APK의 실제 사용 흐름과 스크린샷을 확보하지 않아 화면 기반 감사로 주장하지 않는다. ADB 연결 기기1대는 확인했으며 당시 포커스는 파일 선택 화면이었다. 이번에는 앱 설치나 화면 전환을 실행하지 않았다. 렌즈 보정 결과와 실제 인물 사진 평가는 별도다.

## 최종 적용 구조

1. 기존 사진 선택 → 편집 흐름을 유지한다. 메인 탐색4탭은 바꾸지 않는다.
2. 편집기의 세부 조정에 **기본 / 톤커브 / HSL / 효과 / 왜곡**을 둔다. 내부 편집 항목5개는 가로 스크롤 탭으로 표시해 좁은 패널과 큰 글꼴에서 강제로 압축하지 않는다.
3. 왜곡 탭은 접기 그룹 없이 슬라이더를 바로 보여준다. 기본값 **0 · 꺼짐**, 음수는 **배럴 N**, 양수는 **핀쿠션 N**이다. 수치는 실제 광학 왜곡률이 아니다.
4. 기존 초기화 아이콘과 실행 취소/다시 실행을 사용한다. 같은 기능의 별도 텍스트 초기화 버튼은 제거해 중복을 줄인다. 두 번 누르기 초기화는 보조 조작이며 유일한 수단이 아니다.
5. 설명은 “사진 전체를 변형하며 가장자리가 일부 잘립니다. 렌즈 자동 보정이 아닙니다.”로 제한하고, “레시피·일괄 적용에 포함 · .cube LUT에는 제외”를 별도 안내한다.
6. 미리보기·스크롤 조정 영역·고정 저장 작업의 기존 분리를 유지한다. 사진 저장/레시피 저장 버튼을 왜곡 탭 안에 다시 만들지 않는다. 새로운 작업 배경·카드·장식은 추가하지 않는다.

레시피에 포함되지 않는다는 전제는 현재 구현과 다르다. **현재 레시피에는 왜곡값이 포함되며 LUT에는 포함되지 않는다.** 별도 탭은 조작의 역할을 구분하는 것이고 저장 모델을 사진 전용으로 바꾼다는 뜻은 아니다. 사진별 전용 상태로 분리하려면 레시피/일괄 적용 정책을 별도 요구사항으로 정해야 한다.

## 보류한 대안

- 앱의 메인 탐색에 새 목적지 추가: 편집 중인 작업을 불필요하게 분리하므로 채택하지 않았다.
- 효과 탭의 접기 그룹 유지: 그레인/비네트와 기하 변형을 구분하기 위해 별도 탭으로 옮겼다.
- 제조사 프로파일/계수 선택 UI: 자동 보정 조사와 독립된 수동 효과이며 데이터도 사용하지 않는다.
- 별도 적용/완료 버튼: 기존 편집기의 즉시 미리보기와 저장 흐름을 중복시키므로 추가하지 않았다.
- 작업 영역 배경색·큰 설명 카드: 사용자의 기존 선호와 사진 중심 편집 구조에 맞지 않아 추가하지 않았다.

## 결과와 제한

현재 적용안은 **별도 왜곡 탭 + 방향이 명확한 상태 표시 + 하나의 초기화 수단 + 기존 고정 저장 작업**이다. [기능 사용법](MANUAL_DISTORTION.md)과 [빌드·테스트 기록](verification/2026-11-18/manual-distortion.md)에 연결했다.

실화면 감사·4테마/큰 글꼴·TalkBack·실제 사진 품질을 통과했다고 표시하지 않는다. 다음 UI 검증에서는 편집 진입 → 왜곡 탭 →0/양방향 조절 → 초기화/undo → 고정 저장 작업의 순서로 캡처하고, 실제 사진 평가는 사용자의 후속 진행으로 남긴다.
