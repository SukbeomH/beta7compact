## 후속 개발 단위

1. 이번 기준서·문구·변경 알림 개선을 빌드/lint 확인. 릴리즈·폰 설치는 이번 요청에서 진행하지 않음.
2. 실제 폰에서 4테마 × 세로/가로의 주요 경로, 글꼴100/150/200%, TalkBack을 점검하고 재현 단계를 기록.
3. Figma에서 사진 툴바·카메라 보조 패널·짧은 편집 화면의 비교 시안 작성. 기존 사용자 작업 수와 사진 표시 면적을 기준으로 선정.
4. 선정한 레이아웃을 작은 단위로 적용하고 선택·뒤로가기·저장 작업을 회귀 검증.
5. 검증한 범위와 남은 문제를 기록하고 요청된 배포 시점에 버전 증가·서명·릴리즈.

## 이번 수정 파일

- `UIUX_DESIGN.md`: 공식 자료8개, 선정 규칙12개, 화면별 적용과 체크리스트.
- `docs/UIUX_AUDIT.md`: 현재 검토·우선순위·진행 순서.
- `ui/CameraScreen.kt`: 실험/예정 기능 안내 정합성.
- `ui/PhotosScreen.kt`: 보정 사진 저장 재개 문구.
- `ui/RecipeScreen.kt`: 상태 변경의 polite 접근성 알림.

기존 사진·레시피 데이터 형식과 USB 제어 경로는 변경하지 않는다. 이번 변경은 짧은 문구와 semantics 보완으로, 구현을 그대로 반복하는 신규 단위 테스트는 추가하지 않았다. 실제 저장·카메라 제어는 실행하지 않았다.

## 오픈소스 사례 반영 재평가

[추가 조사](UIUX_OPEN_SOURCE_REFERENCES.md) 결과, 단순 툴바 높이 축소보다 편집 화면의 미리보기·스크롤 조정·고정 주 작업 골격을 먼저 검토한다. 이어 사진 선택 문맥과 보조 복구 작업 노출을 정리한다. 이미지 디코딩 크기 제한과 로컬 URI 썸네일 재사용을 새 성능 검토 항목으로 올렸다. 캐시 용량 상한이 순간 디코딩 메모리까지 보장하지 않는다는 점을 구분한다. 라이브러리 교체·아키텍처 전면 개편은 보류하며, 상세 수정 순서는 추가 조사 문서의 순서를 따른다. 이번 추가 검토에서 앱 코드를 변경하거나 검증을 새로 실행하지 않았다.
