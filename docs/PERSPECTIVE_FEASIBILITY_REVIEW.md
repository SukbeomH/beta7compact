조사일: 2026-11-17. 결론: **기능의 탐색 가치는 있으나, 다른 채팅의 미검증 프로토타입을 그대로 현재 앱에 병합하는 것은 권하지 않는다.** 원래 요구한 얼굴3D/가상카메라 구현과 실제 작성된2D 변형을 구분하고 소규모 품질 실험을 먼저 진행한다.

## 왜 고려할 가치가 있는가

α7C 사진 가져오기→LUT 편집→별도 JPEG 저장 흐름에서 인물 보정은 자연스러운 확장이다. 광각 사진의 화면 가장자리 인물, 가까이 촬영한 얼굴은 단순 색 보정으로 해결할 수 없는 문제다. 다만 사용자 사진 빈도/실패 사례를 아직 수집하지 않아 수요나 품질 개선 효과는 확인되지 않았다. 인물 중심 사용 빈도가 높고 실제 샘플에서 기존 편집보다 선호될 때 가치가 커진다는 판단이다.

## 구별해야 할 네 가지 문제

| 문제 | 필요한 접근 | 이번 코드와의 관계 |
| --- | --- | --- |
| 건물 수직선/문서 사다리꼴 | 평면 투시/호모그래피·회전·크롭 | 얼굴 목표와 별도 기능. 현재 구현되지 않음 |
| 렌즈 배럴/핀쿠션 왜곡 | 렌즈/촬영 모드의 보정 계수 | 임의 방사형 변형을 렌즈 프로파일 보정이라 부를 수 없음 |
| 화면 가장자리 얼굴 신장 | 얼굴 영역 인식+국소 투영/메시와 배경 직선 제약 | 연구 근거 있음. 현재의 단일 방사형 변형은 배경을 함께 구부릴 수 있음 |
| 가까운 얼굴의 코/귀 비율 | 깊이/형상 가정과 가상 시점 이동 | 단일 JPEG만으로 정확한 깊이·가려진 부분 복원 불가. 현재 코드는3D 재투영 아님 |

원근 변화는 촬영 위치와 피사체 깊이의 관계에서 발생한다. 같은 위치의 사진을 단순 크롭하거나 초점거리 숫자만 바꿔도 촬영 거리가 달라진 얼굴을 복원할 수는 없다. 35/50/85mm 버튼은 깊이/거리·센서/크롭 가정이 없는 상태에서 물리적 렌즈 재현을 보증하지 않는다. 핸드오프의 GEOMETRY.md도 이를 명시한다.

## 공개 연구/도구 근거

1. [Shih et al., SIGGRAPH2019](https://people.csail.mit.edu/yichangshih/wide_angle_portrait/): 얼굴 영역은 stereographic 쪽으로, 배경은 perspective 쪽으로 이어지는 content-aware mesh 최적화를 제안한다. 주변부 인물 보정과 배경 보존의 연구 근거다. 사이트의70~120도 FOV 결과를 α7C28mm JPEG 성능으로 그대로 일반화하지 않는다.
2. [Tan et al., CVPR2021 논문](https://openaccess.thecvf.com/content/CVPR2021/papers/Tan_Practical_Wide-Angle_Portraits_Correction_With_Deep_Structured_Models_CVPR_2021_paper.pdf): 얼굴 형상·배경 선·전환을 함께 다루는 접근이다. [저자 저장소](https://github.com/TanJing94/Deep_Portraits_Correction)의 조회 시점 기본 트리는 README/figures 중심이며 README의 Linux/PyTorch/CUDA 안내가 Android용 즉시 사용 패키지를 뜻하지 않는다.
3. [ECCV2024 DualPriorsCorrection](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/04272.pdf), [저자 저장소](https://github.com/Dev-Mrha/DualPriorsCorrection): 생성/기하 사전정보 결합의 후속 연구. 후보 연구 자료이며 이번에 모델 가중치·모바일 변환·라이선스/전체 의존성 적합성·실행 성능은 검증하지 않았다. 바로 도입하지 않는다.
4. [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker): 얼굴 랜드마크와 효과 렌더링용 변환 행렬을 제공한다. 얼굴 위치/선택 보조 후보로 적합하지만, 출력이 실제 피사체의 정확한 깊이·거리나 얼굴 원근 보정 자체를 보장하지 않는다. 사용 모델의 이용 조건/배포 크기/기기 성능은 별도 확인해야 한다.
5. [OpenCV 기하 변환](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html): 역방향 매핑·보간·경계 처리의 구현 근거. 2D 이미지 변환 도구이며 그 자체로 얼굴3D를 추정하는 엔진은 아니다.
6. [ExifTool Sony 소스](https://github.com/exiftool/exiftool/blob/master/lib/Image/ExifTool/Sony.pm): Sony 메타데이터 해석의 조사 출발점. 태그 존재만으로 α7C+특정 렌즈의 절대 촬영거리 변환을 검증한 것은 아니다. 공식 Sony AF 명령/거리 보장으로 해석하지 않는다.

## 타 채팅 구현의 실제 상태

| 항목 | 확인 결과 | 통합 판단 |
| --- | --- | --- |
| 얼굴 위치·반경 수동 설정 | 타원 영역에2D 중심 수축을 적용 | 국소 변형 실험 재료. 자연스러운 얼굴 보정 품질은 미측정 |
| 35/50/85 선택 | 초점거리 비율을 변형 강도 계산에 사용 | 물리적 촬영 결과를 오인할 수 있어 명칭/가정 변경 필요 |
| 재투영 수학 | Intrinsics/retreat/scale 및 테스트 작성 | 실제 PixelWarp의 얼굴 변형에는 이 깊이 재투영 계산을 사용하지 않음 |
| 얼굴3D·검출·다중 얼굴 | 없음 | 원래 목표 미달 |
| EXIF | 초점거리·환산·렌즈·거리 일부 읽기 | 일부 활용 가능. MakerNotes/AF 미지원, 알 수 없는 초점거리는28mm 기본 가정 |
| 주변부 보정 | 전체 프레임 방사형 변환+경계 clamp | 직선 휨·경계 신장 위험. 얼굴 선택 마스크와 선 보존 필요 |
| 미리보기/출력 | CPU 전체 픽셀 순회, 미리보기1200/출력4096 긴 변 상한 | 실시간 성능·메모리 미측정. 취소/오류/OOM 제어 보완 필요 |
| 저장 | 별도 Pictures/Perspective JPEG, EXIF/ICC 복사 없음 | 현 앱의 결과 연결/저장 경로/색 정책과 분리돼 있음 |
| 검증 | 다른 환경에서 SDK 설정 오류로 빌드/테스트/lint 미실행 보고 | 현재 실행 가능한 MVP로 취급하지 않음 |

메모리 위험은 코드에서 추정했다.4096×4096 RGBA 버퍼 한 개는64MiB다. 입력 Bitmap·입력 IntArray·출력 IntArray·출력 Bitmap을 만드는 경로에는 수백MiB급 순간 할당 가능성이 있다. 이는 최악 입력의 산술 추정이며 실제 폰 측정값이 아니다. 디바운스120ms가 처리 시간이나 취소를 보장하지 않으며 픽셀 루프에는 협력적 취소 확인이 없다.

## 현재 앱 통합에서 해결해야 할 충돌

- 다른 기준의 MainScreen 변경을 통째로 가져오면0.8.4 선택 작업줄/가로 배치와 충돌할 수 있다. 핵심 엔진과 UI 연결을 별도 검토해야 한다.
- 현재 Recipe v1/v2에는 색 보정 상태만 있다. 얼굴 좌표/마스크 같은 사진별 기하 정보는 다른 사진에 일괄 재사용되는 LUT 레시피와 분리해야 한다.
- 기존 GpuEngine의 색 변환은 타일 단위다. 기하 변환은 다른 타일의 픽셀을 샘플링할 수 있어 현재512타일 처리에 단순 끼워 넣으면 이음새/범위 오류가 생길 수 있다.
- 사진 방향을 먼저 정규화한 좌표계, 얼굴/크롭 좌표, 프리뷰와 원본 해상도 사이 매핑을 일치시켜야 한다.
- 결과 URI를 기존 라이브러리와 연결하고 저장 위치·원본 보존·JPEG 품질·메타데이터/GPS/색공간 정책을 명확히 해야 한다. 현재 별도 picker/저장은 가져온 사진에서 편집하는 흐름과 달라 추가 JPEG 재압축이 생길 수 있다.
- LUT 전 단계의 기하 변환과 한 번의 최종 인코딩을 기본 후보로 검토한다. 그레인·비네트·크롭의 좌표 기준도 함께 정의한다.
- MakerNotes를 필수 선행조건으로 삼지 않는다. 검증되지 않은 초점 모터 위치를 미터 단위 거리로 변환하거나 α7C전용 명령을 새로 보내지 않는다.

## 권장 도입 순서와 판정 기준

1. **오프라인 품질 실험부터:** 현재 릴리즈와 격리. 동의받은 인물 샘플에서 중앙/가장자리,1인/다인, 안경/손·머리카락 가림, 배경 직선이 있는 경우를 모은다. 얼굴 중앙의 근거리 왜곡과 주변부 신장을 따로 평가한다.
2. **수동 국소 보정 비교:** 얼굴 위치를 사진 위에서 지정하고 낮은 강도의 변형을 비교한다. ‘장초점 렌즈 재현’ 대신 ‘인물 형태 보정·실험’으로 표시. 적용 취소/기본 꺼짐/원본 비교 제공. 타 채팅 코드는 아이디어/실험 재료로만 선별 재사용.
3. **품질 게이트:** 원본 대비 선호, 얼굴 닮음 유지, 눈·입·턱선 비대칭/배경 직선 휨/경계 신장을 기록. 같은 위치 크롭과 실제 카메라를 물리적으로 이동한 사진을 구별해서 비교한다. 효과가 없거나 부자연스러운 사례도 보관. 성능은 기기별 median/p95와 최대 메모리를 측정하고 측정 후 예산을 정한다.
4. **랜드마크 보조:** 품질이 확인된 변형에만 얼굴 검출/선택 자동화를 추가. MediaPipe는 후보이며 다중 얼굴 독립 선택·거부·가림 처리 필요. 정확한3D/촬영거리 복원이라고 표시하지 않는다.
5. **현재 편집기/저장 통합:** 얼굴별 사진 전용 상태, undo/redo, 안전한 원본 크기 출력/취소, 결과 연결·메타데이터·색 정책과 회귀 검증 후 실험 배포.

첫 실험에서 유의미한 개선이 없으면 얼굴 보정은 중단/보류하고, 별개 수요가 있는 회전·크롭·수직/수평 투시 보정을 우선 검토할 수 있다. 이는 본래 코 돌출 개선 요구를 충족했다는 뜻은 아니다.

## 최종 추천

- **조건부 채택:** 광각 인물의 국소 형태/주변부 신장 개선. 앱과의 적합성이 있으나 실제 사용자 사진의 선호 검증 필요.
- **보류:**3D 얼굴 재구성·85mm 촬영 재현·Sony AF 기반 절대 거리 추정의 일괄 도입. 비용/불확실성이 크고 현재 프로토타입이 이를 구현하지 않음.
- **즉시 병합 비추천:** 미검증 빌드,2D/3D 목표 차이, 출력 품질/메모리/현재 저장 체계 충돌을 먼저 해결해야 함.

현재 이미지 로딩3단계와 접근성 검증을 대체하는 긴 개발로 바로 전환하기보다, 별도 품질 실험 결과를 먼저 보고 우선순위를 결정하는 것이 적절하다. 이번 수정 파일은 이 조사 문서 하나다.
