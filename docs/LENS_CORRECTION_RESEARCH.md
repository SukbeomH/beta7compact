# 수동 국소 보정 종료와 렌즈 왜곡 보정 조사

2026-11-18. 수동 국소 보정은0.8.5에서 품질 평가용으로 제공했으나0.8.6에서 제거한다. 얼굴과 배경의 자연스러움이라는 목적을 충족하지 못했다. 강도 조절이나 얼굴 검출 추가만으로 확장을 계속하지 않는다.

## 실기 피드백과 확인 범위

사용자는 “화면이 아니라 보정된 얼굴과 배경이 어색해. 이런 식이면 그냥 기능 없애는게 낫겠는데”라고 보고했고, 이후 기능 제거와 조사 결과 문서화를 요청했다. 화면 배치에 대한 불만이 아니라 사진 결과에 대한 부정적 품질 평가다.

원본/보정 사진, 입력 크기, 중심·반경·강도, 렌즈·촬영 거리 및 폰 정보는 이번 피드백에 첨부되지 않았다. 개발자가 해당 사진을 직접 비교하거나 정량 평가한 것은 아니다. 모든 사진에서 실패한다고 일반화하지 않지만, 목적에 맞는 품질이 입증되지 않은 실험을 앱에서 종료할 근거로 판단했다.

0.8.5의 Debug/Release 각353개 테스트에는 합성 픽셀·입력 복사·출력 실패/취소 검사가 포함되어 있었다. 얼굴 닮음·배경 자연스러움이나 실제 Android JPEG 저장 품질을 검증한 테스트가 아니다. [당시 검증 기록](verification/2026-11-18/release-0.8.5.md)은 과거 실행 결과로 보존한다.

## 현재 방식에서 확인한 한계

제거 전 `LocalWarp.kt`는 사용자가 지정한 원 안에서 역방향 방사형 매핑과 bilinear 보간을 수행했다. 변형식은 `sourceRadius = outputRadius * (1 + a * (1-r²)²)`, `a <= 0.15`였다. 경계에서 변형량이0이 되더라도 내부의 얼굴 비율과 배경 직선을 보존하지 않는다.

얼굴/배경 분리, 깊이, 실제 렌즈의 왜곡 계수, 카메라 보정 정보가 없으므로 얼굴과 뒤의 배경에 같은 변형이 적용된다. 이는 사용자 증상의 가능한 구조적 원인이며 특정 사진의 실패 원인을 재현해 확정한 것은 아니다. 강도를 낮추면 변형이 줄지만 필요한 개선까지 줄어든다. 얼굴 검출로 중심을 자동 지정해도 이 변형 모델의 한계는 남는다.

## Lightroom이 다루는 서로 다른 문제

| 기능 | 대상 | 현재 실험과의 차이 |
| --- | --- | --- |
| 렌즈 프로파일 보정 | 렌즈의 배럴·핀쿠션 왜곡, 주변부 밝기 등 | EXIF로 카메라·렌즈를 식별하고 해당 프로파일 사용 |
| 수동 왜곡 조정 | 사진 전체의 배럴·핀쿠션 왜곡 조절 | 얼굴 원 안의 임의 수축과 목적이 다름 |
| Upright/Geometry | 수평선 기울기, 건물의 수직선 수렴 등 | 사진의 선/기하 관계를 이용하는 별도 원근 보정 |
| 얼굴 원근/주변부 형태 보정 | 근거리 얼굴 비율 또는 화면 가장자리 인물 신장 | 렌즈 프로파일이나 Upright만으로 해결을 보장하지 않음 |

Adobe는 EXIF로 식별한 카메라·렌즈에 맞는 프로파일을 적용한다고 설명한다. 자동 선택이 안 되면 제조사·모델·프로파일을 수동 선택한다. 프로파일의 왜곡 보정량100은 기준 보정량이며 얼굴의 정확한 복원율이 아니다.[1]

일반적인 기하 보정은 사진 전체의 픽셀 좌표를 다시 계산하고 보간하는 방식으로 이해할 수 있다. 주변부 신장·리샘플링에 따른 디테일 변화·유효 영역 크롭이 생길 수 있다. 이 설명은 일반적인 영상 기하 원리이며 Adobe의 비공개 내부 수식/렌더링 순서를 확인했다는 뜻은 아니다. 직선을 곧게 만드는 목적과 얼굴을 자연스럽게 보이게 하는 목적은 일치하지 않을 수 있다.

근거리에서 코가 상대적으로 커지는 원근은 촬영 위치와 얼굴의 깊이 관계에서 발생한다. 단일 사진의 초점거리 숫자나 보정 강도만 바꿔 멀리서85mm로 촬영한 모습을 정확히 복원할 수 없다. 화면 가장자리 얼굴의 신장도 광학적 배럴 왜곡과 구분해야 한다. [기존 원근 보정 조사](PERSPECTIVE_FEASIBILITY_REVIEW.md)에 관련 연구와 한계를 보존한다.

Adobe는 렌즈 프로파일을 먼저 적용한 후 Upright를 실행하도록 권장한다. 렌즈 보정과 원근 분석을 별도 작업으로 취급한다.[3]

## α7C와 JPEG의 중복 보정

Adobe는 RAW와 비RAW의 프로파일을 구분하고, JPEG는 생성/이전 처리에 따라 예상 밖 결과가 날 수 있다고 명시한다.[2] Sony α7C는 대응 렌즈에서 주변부 밝기·색수차·왜곡 보정을 제공하며 렌즈에 따라 왜곡 보정을 끌 수 없다.[4] Sony는 RAW+JPEG 촬영에서 JPEG에는 렌즈 보정이 적용되고 RAW 자체는 보정되지 않는다고 안내한다.[5] RAW 뷰어가 자체 보정을 적용해 표시하는 것과 원본 픽셀의 보정 여부는 구분해야 한다.

따라서 카메라에서 가져온 JPEG에 미보정 RAW용 변환을 그대로 적용하지 않는다. EXIF에 렌즈 이름이 있다는 사실만으로 보정 계수나 이미 보정됐는지 여부를 확정할 수 없다. α7C 바디 지원 여부만으로 모든 E마운트 렌즈/촬영 모드에 대한 보정을 지원한다고 표시하지 않는다.

## 제거 범위와 이후 판단

0.8.6에서 설정 진입/제목, 실험 화면, 국소 변형 엔진, 전용 입력/출력 코드5개와 전용 테스트3개를 제거한다. 공용 편집기·LUT·레시피·저장·가져오기·진단·PC Remote/AF·촬영은 수정하지 않는다. 과거 문서와 빌드 로그는 기능 종료 표시와 함께 보존한다.

이미 저장한 `Pictures/beta7compact/Experiments/`의 JPEG와 원본 사진은 삭제하지 않는다. 이전 버전의 `cache/local-warp-inputs`가 남아 있다면 앱 전용 캐시이며 새 버전은 사용하지 않는다. 이번에는 데이터 삭제용 마이그레이션을 추가하지 않는다. Android의 캐시 정리 또는 사용자의 앱 캐시 삭제 대상이다. 레시피/DB 스키마 변경은 없다.

후속 렌즈 보정은 별도 제안이며 이번에 구현하지 않는다. 실제 사용 렌즈와 촬영 설정·RAW/JPEG·보정 상태를 먼저 확인하고, 검증된 프로파일 또는 직접 측정한 계수와 사용/배포 조건을 확보한 경우에만 검토한다. Adobe 프로파일을 앱에서 자유롭게 재배포할 수 있다고 가정하지 않는다. 직선·크롭·중복 보정·해상도·인물 자연스러움까지 비교해야 하며, 얼굴 보정의 대체품이라고 소개하지 않는다.

## 출처와 검증의 한계
